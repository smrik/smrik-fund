## Findings

### A1-1 [P1] row-selector evolution can false-split one approved identity

`_target_row_key()` changes representation when source shape changes: a unique
standard concept becomes `standard_concept:C|label:A` when a duplicate row
appears, and falls back to `label:A` when `standard_concept` disappears
(`src/smrik_fund/main.py:178-249`). `_history_identity_lookup()` compares the
four identity components exactly and only treats an exact target-row key as
occupied (`main.py:329-382`). A fresh `.venv` probe with the same MSFT/period/
`same-charge` candidate returned `standard_concept:C` before the shape change,
`label:A` after it, and lookup status `new` against approved `A0001`; the
unique-to-qualified variant likewise returned `new`. The new-ID branch then
allocates a provisional ID (`main.py:1151-1157`). This can create a second
canonical history ID for the same economic event, violating occupied-row
false-split protection. Either preserve one canonical selector across schema
drift or fail closed when an occupied row-period has a changed selector.

### A1-2 [P2] company identity is not canonicalized before exact matching

`_candidate_identity()` normalizes the run ticker to uppercase, but
`identity_components()` accepts any non-empty company string
(`src/smrik_fund/ingestion/adjustments.py:64-81`, `main.py:267-297`). A fresh
probe with persisted identity company `msft` and candidate company `MSFT`
returned `new`, not `identity_unresolved`, so a malformed/case-drifted v2 row
can mint a second ID. Strict history validation should reject non-canonical
company values (or otherwise block the occupied company/period).

### A1-3 [P2] docs omit the inert-legacy exception actually used

The validator intentionally skips identity-less `proposed`/`rejected` rows
(`src/smrik_fund/ingestion/adjustments.py:151-161`), and new candidates then
receive provisional IDs (`main.py:1151-1157`). Section 2 only says “Legacy or
corrupted history fails closed” without distinguishing inert workflow rows from
approved/effective or malformed legacy (`docs/ai_fund_v1_section_2_implementation_spec.md:934-941`).
The manifest evidence correctly reports the old all-proposed history as inert
and the new `A0024`–`A0031` IDs as provisional, but the durable docs should say
this explicitly.
