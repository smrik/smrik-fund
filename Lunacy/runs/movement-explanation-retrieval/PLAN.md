# Movement-explanation retrieval — Implementation Hive

Mode: full Implementation Hive explicitly requested. Sequence: diversity -> synthesis/implementation -> read-only simplicity/financial review -> parent gate.

## Phase 1 — diversity

Three independent fresh Luna scouts inspect the same authority and repository. Read-only except their own proposal files. Each proposes the smallest architecture-preserving retrieval improvement, affected surfaces, invariants, risks/proof, and size.

## Phase 2 — synthesis and implementation

One fresh max-effort Luna judges all proposals, chooses the simplest sound design, implements end-to-end, adds focused regressions, runs required full verification, and produces fresh MSFT Findings 1-3 live artifacts/comparison. It owns only minimum current retrieval/investigation/prompt/test surfaces and its report/output artifacts.

## Phase 3 — read-only reviewer

One fresh xhigh Luna is strictly read-only for source/tests/live outputs. It performs the user-requested financial correctness, leakage, evidence, ambiguity, usefulness, regression, and simplicity review. Defects route to a separately authorized repair; no silent edits.

## Phase 4 — parent gate

Parent reads terminal Control Blocks, targeted final diff/code slices and live comparison, runs a bounded acceptance sample, and issues PASS or DO NOT MERGE. No extra gate scout: one coherent writer is planned and the explicit fresh reviewer supplies the independent read-only review.

## Gates

- Phase 1: three independent proposals terminal.
- Phase 2: final code, required checks, and live Findings 1-3 proof terminal.
- Phase 3: fresh read-only report terminal; any required repair reopens write barrier and invalidates stale proof.
- Phase 4: parent independently confirms grounding, financial safety, usefulness, simplicity, and final-state verification.
