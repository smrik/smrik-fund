# P2 — deterministic movement-aware evidence ordering

## Approach

Add one small deterministic ranking step inside the existing literal retrieval path. After exact `filing.text()` matches are rendered (and before `E##` IDs are assigned), score each unchanged excerpt using a generic financial-movement cue lexicon (`increased`, `decreased`, `driven by`, `due to`, `offset by`, gains/losses, and comparable inflections) and a lower-priority static cue lexicon (`includes`, `consists of`, `comprises`, `classification`, `defined as`, `expensed as incurred`). Sort by movement hits descending, static hits ascending, then the existing source offset/query-index/search-locator tie-breakers. This changes attention order only; it does not filter, paraphrase, or infer causality. Keep the existing `MAX_EVIDENCE_ITEMS` overflow failure and static-only source-order fallback. Optionally record an additive metadata field identifying the ordering method.

## Exact affected surfaces

- `src/smrik_fund/ingestion/filing.py`: add local cue patterns/ranking helper; apply it only to literal items in `_retrieve_filing_evidence` before numbering. Preserve `_source_matches`, locator construction, packet rendering, and regex/legacy retrieval behavior.
- `tests/test_filing.py`: focused fixture with static and movement excerpts for one literal query; assert movement comes first, exact excerpts/offsets/provenance remain intact, and a static-only fixture still retrieves.
- Regression only (no edits expected): `src/smrik_fund/ingestion/filing_investigation.py` (`_select_initial_queries` and expansion orchestration), `src/smrik_fund/main.py` shared retrieval caller, `tests/test_discovery.py`, and `tests/test_filing_investigation.py`.
- No prompt, query-derivation, analytical-scan, extraction, reconciliation, adjustment/history, or live-artifact source changes.

## Invariants

- Initial seeds remain closed-world and deterministic; ranking reads only the exact source excerpt, never the finding, ticker, model, web, or company vocabulary.
- Every item remains a contiguous `filing.text()` excerpt with its original query, section locators, accession, source line/offset metadata, and valid packet identity.
- No item is discarded or rewritten by ranking; static definitions remain available when no stronger movement excerpt exists.
- Expansion remains one packet-grounded pass, with exact first-pass refs/spans and no extra search loop; E IDs remain valid within each packet.
- No arithmetic, sign/period mapping, driver allocation, adjustment write, or model-state mutation changes.

## Non-goals

No LLM reranker, embeddings/RAG, new query generation, company-specific cue list, deduplication/schema migration, broad query-budget change, or causal claim from cue presence. No ranking of analytical findings or model drivers.

## Risks / proof

Generic words can occur in a risk or definition passage. Because this is ordering-only, exact provenance and the complete bounded packet remain available; the Financial Investigation validator still decides what is supportable. Prove with focused static-vs-movement and static-fallback tests, then run existing filing/investigation/discovery tests and the required real MSFT Findings 1–3 path. F1 must retain the exact paired disclosure and Python bridge (`+15.598bn` observed, `+11.3bn` disclosed, `+4.298bn` unresolved, plug false); F2 should remain usable static fallback; F3 should surface the operating/sales movement lines before definitions.

## Estimated size / complexity

Low: one local helper plus a literal sort-key branch (roughly 15–30 production lines) and two or three focused tests; no new module or interface.
