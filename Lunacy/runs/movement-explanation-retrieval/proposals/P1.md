# P1 — deterministic movement-first initial queries

## Approach

The current initial pass is closed-world and deterministic, but it searches
mostly bare labels (or the static `included` cue). `_select_initial_queries`
then accepts the first literal hits in affected-line order. This explains the
live quality gap: Finding 2 starts with `Service and Other` and returns static
revenue definitions; Finding 3 starts with `Sales and marketing` and returns
employee/definition/table text before the movement sentence.

Keep the existing `FindingSearchPlan`, literal EdgarTools retriever, evidence
budget, and expansion boundary. Add a private bounded candidate generator in
`filing_investigation.py`:

1. For each affected source row, preserve the exact safe source label and use
   only a tiny generic qualifier inferred from the supplied concept/standard
   concept (`revenue`, `costs`, `expenses`, or `income`) when the label omits
   that noun. This is lexical context, not a taxonomy or mapping.
2. Emit movement-led literal candidates in a fixed order: the qualified/direct
   subject with `increased`, `decreased`, `driven by`, `due to`, and `offset`
   (only exact literal phrases that happen to occur will survive). Retain the
   current label/`included` form as the static fallback.
3. Make `_select_initial_queries` evaluate all bounded candidates against the
   filing text, rank exact movement-cue candidates ahead of static candidates,
   preserve affected-reference order within a cue tier, apply the existing
   occurrence/evidence budget, and accept at most `MAX_QUERIES`. Persist all
   candidate/rejection derivations and only accepted derivations under the
   existing metadata keys. `FindingSearchPlan.queries` remains the accepted
   literal set (never more than three); the pre-retrieval builder itself makes
   no model call and sees no filing text.

This permits a filing-local movement sentence to win when both movement and
definition hits exist, while the known Finding 1 `... included` seed remains a
safe fallback if no movement phrase is present. No query contains a raw amount,
year, ticker, or cause from filing text; period labels may remain artifact
context but are not needed as search vocabulary.

## Invariants

- Closed-world source: each initial query is composed only from a supplied
  affected source label/concept plus the fixed generic allowlist; generator
  input never includes filing text, ticker, company name, finding prose,
  answer terms, amounts, or invented causes.
- Generic qualifier safety: concept-derived nouns are an explicit finite
  lexical allowlist; ambiguous/unsafe labels are skipped rather than mapped.
- Determinism: same finding/context yields the same casefold-deduplicated
  candidate and accepted order; affected-line order is stable; each query is
  literal, <=240 characters, and accepted count is <=3.
- Preference is conditional: exact movement-cue hits outrank exact static
  hits; if movement candidates have no safe literal hit, the existing static
  label/`included` seed remains usable. Rejections and overflow stay visible.
- Existing evidence item limits, exact source offsets, accession/source checks,
  Python arithmetic, sign/period/unit validation, and state isolation remain
  unchanged.
- Expansion still starts only after an exact initial packet and remains one
  filing-grounded pass; no retries, loops, embeddings, RAG, or web search.

## Non-goals

No new retriever, ranking framework, taxonomy, semantic model, web/browsing
path, period inference, normalization, forecast/valuation/action logic,
adjustment or history write, prompt-based security boundary, or broad refactor
of the 2,500-line investigation module. Do not alter the current Filing
Evidence API to support partial retrieval; if candidate handling requires a
shared retriever change, stop for a scope decision.

## Risks and proof

The main risk is filing wording mismatch: a concept-derived `costs` or
`expenses` phrase may not be contiguous in a particular filing, and a movement
phrase may be too common. Exact literal-hit checks plus the existing 20-item
budget reject such candidates; the static fallback prevents a false invented
cause. A second risk is that a movement hit still contains no usable driver;
that is acceptable—the Analyst must report absence/ambiguity and expansion
remains bounded.

Focused proof should use a fake filing containing both, for example, a static
`Sales and marketing expenses include ...` sentence and a contiguous
`Sales and marketing expenses increased ... driven by ...` sentence. Assert the
initial packet/query uses the movement phrase, while a fixture with only the
static sentence falls back without an LLM planner. Assert no `OpenAI` enters
initial candidates when it appears only in filing text, and verify derivation
refs/cues and <=3 accepted literals.

Terminal live proof should rerun the same MSFT accession for Findings 1–3. The
Finding 1 positive control must retain observed `+15.598bn`, disclosed
`+11.3bn`, unresolved `+4.298bn`, and `difference_is_reported_plug=false`;
its known `... included` path must remain available. Findings 2/3 should show
movement evidence in the initial packet when exact phrases exist, with static
fallback/absence explicitly reported otherwise. Compare initial queries,
accepted/rejected derivations, strongest evidence, one-pass expansion, and
final analyst outputs; ensure no adjustment/history/adjusted-P&L files appear.
