# P3 — Evidence integrity and focused verification

Scope: make the real filing packet safe to consume and prove the acceptance
points around exact excerpts, provenance, call limits, and history hygiene.

## 1. Approach

- Keep retrieval narrow to the first MSFT topic. Use EdgarTools' latest `10-K`
  filing and its filing text/search facilities. Do not add an SEC downloader,
  HTML scraper, RAG layer, vector index, or generic retrieval framework.
- Render each evidence item from the filing text without reflow, paraphrase,
  numeric conversion, or whitespace normalization. Sort matches by source
  offset/line and assign deterministic `E1`, `E2`, ... IDs. If a bounded
  follow-up retrieval is needed, append new items without renumbering the
  existing packet.
- Add one small packet parser/validator (plain dicts are sufficient). It should
  reject duplicate/non-positive IDs, empty excerpts, malformed item headers,
  and missing filing identity/locator metadata. A locator must state what was
  actually observed (accession plus source attachment and line/offset); do not
  claim a section or line that EdgarTools did not provide.
- Validate every Analyst candidate's evidence refs against the validated packet
  before persistence, and use the same ID check before the Reviewer call.
  Unknown refs or malformed packet content fail closed: no model call, result
  save, history write, or application.
- Carry only the small provenance fields needed by downstream artifacts:
  `filing_accession`, `evidence_file`, and `topic` (plus existing source/locator
  data). Keep long excerpts in the Markdown packet, not CSV history.
- Keep Analyst behavior high-recall. If the implementation truly needs a
  research signal, add at most one nullable request field and allow one
  retrieval plus one Analyst resolution call; otherwise keep the existing
  schema. Never infer an amount from a parent-line change or other unsupported
  context; retain `null`.
- Treat an `analyze --adjustments` run as exploratory until the existing
  authorized history transition. Unresolved/human-review candidates must not
  append to `adjustment_history.csv`, become current adjustments, or change
  the adjusted P&L. Approved candidates must continue through the existing
  deterministic engine only.

Concrete repository observation: the local latest MSFT 10-K is accession
`0001193125-26-323660` (FY2026). Its source text has the relevant operating
expense sentences on lines 1266 and 1283. The checked-in packet currently
wraps those sentences across Markdown lines, so it should not be treated as
an exact-source packet by the new path.

## 2. Changed surfaces

- `src/smrik_fund/ingestion/evidence.py` (or one equivalently local module):
  narrow EdgarTools retrieval, packet rendering, provenance, and strict
  validation. Avoid a provenance graph or a hierarchy of evidence classes.
- `src/smrik_fund/ingestion/adjustment_analysis.py`: validate the packet before
  the API call; preserve the current minimal candidate schema and null amounts,
  adding only a minimal research-request field if the one-resolution flow
  cannot otherwise be represented.
- `src/smrik_fund/ingestion/reviewer.py`: call the shared packet/ref validator
  before the Reviewer API call; keep Reviewer output and conservative behavior.
- `src/smrik_fund/main.py`: obtain the packet through EdgarTools for
  `--adjustments`, pass and persist provenance, cap Analyst retrieval/resolution
  at one follow-up, and do not append exploratory unresolved candidates to
  canonical history.
- Focused tests may be added in `tests/test_filing_evidence.py` and/or the
  existing Analyst/integration test files. Do not modify the gold fixture or
  use it at runtime. Generated `data/MSFT` artifacts are verification output,
  not source-of-truth inputs.

## 3. Invariants

1. Filing identity comes from the EdgarTools filing object (ticker, form,
   accession, report date, and honest source URL/path), never from the gold
   evaluation note or an answer-hardcoded prompt.
2. Reassembling an evidence excerpt from its packet representation yields the
   exact source substring, including source line boundaries. Markdown quote
   markers are formatting only and must not alter the stored text.
3. Evidence IDs are unique and deterministic within a packet; adding a
   follow-up item does not change the IDs already cited by a candidate.
4. Every cited ID resolves to a non-empty excerpt with provenance. Duplicate
   IDs, unknown IDs, missing excerpts, and unhonest locators fail closed before
   model/persistence side effects.
5. The model input contains only neutral instructions, the reported P&L, and
   the retrieved packet. It contains no `tests/msft_restructuring_gold.md`,
   expected target/amount labels, or evaluation answer.
6. There is at most one bounded research retrieval and at most one subsequent
   Analyst resolution call; no endless research/revision loop is introduced.
7. Unsupported attributable amounts stay `null`; no code or prompt turns a
   parent-line increase into a disclosed sub-item amount.
8. Reviewer/gate failures, null amounts, and uncertain provenance remain
   human-review/unapplied. They do not create an approved current adjustment,
   mutate reported source rows, or make adjusted P&L differ from reported P&L.
9. Only the existing authorized state transition may append history. An
   exploratory run may save analysis/review/manifest artifacts, but must leave
   an existing history file byte-for-byte unchanged when no authorized
   approval occurs.
10. Approved rows still resolve latest-version-first and use the existing
    adjustment engine; no second application or special LLM path is added.

## 4. Non-goals

- No vector DB, embeddings, RAG framework, cryptographic evidence store,
  provenance graph, custom SEC cache, or new model/provider abstraction.
- No generic cross-company/topic retrieval system, answer-specific packet
  names, or gold/eval data in production prompts.
- No fuzzy target/period/amount matching and no amount estimation added merely
  to satisfy the known MSFT case.
- No history-schema rewrite, human-review CLI redesign, or extra Reviewer loop.
  Preserve unrelated Task 7/8/9 behavior and dirty worktree changes.
- No broad package or dependency upgrade. Real-data production retrieval must
  use EdgarTools; local filing text may be a test fixture only.

## 5. Risks / verification

The key integrity risk is confusing EdgarTools' ranked/search-rendered section
text with the original filing text. Tests should build a fake filing with
known line boundaries, then assert the packet excerpt is an exact contiguous
substring and that accession/attachment/line locators are correct. The real
MSFT fixture should assert the FY2026 accession and the two known operating
expense passages without asserting the gold answer in the prompt.

Focused checks:

- Retrieval: fake EdgarTools filing produces deterministic E1/E2, exact text,
  stable ordering, required identity, and no paraphrase/reflow.
- Validation: duplicate IDs, missing metadata/excerpts, malformed packets, and
  unknown candidate refs fail before `responses.parse`, artifact saves, or
  history writes.
- Prompt isolation: capture Analyst inputs; assert only P&L plus packet and
  neutral instructions are present, and gold/evaluation labels are absent.
- Call budget: fake client records calls. A normal path makes one Analyst call;
  a research-request path makes exactly one retrieval and one resolution call,
  never a third. The resolution packet preserves old IDs and leaves an
  unsupported amount null.
- Reviewer: packet is passed unchanged; unknown refs fail before the model;
  accepted/revise/reject output remains conservative and does not rewrite the
  candidate.
- Integration: unresolved candidate leaves `adjustment_history.csv` absent or
  unchanged, leaves current approved adjustments and source P&L unchanged, and
  reports `not_applied`. A separately seeded approved fixture proves only the
  authorized transition appends and applies once with provenance fields.
- Run `pytest` for the focused evidence/Analyst/Reviewer/integration tests,
  Ruff on changed Python, `git diff --check`, then the real
  `analyze MSFT --adjustments` path and inspect the packet/manifest/history.

The real EdgarTools inspection was attempted with version 5.45.1, but the
environment's SEC socket access was denied (`WinError 10013`) and the default
Edgar cache was ACL-protected. The local downloaded filing and `filing_index`
provide read-only confirmation; terminal acceptance still needs a network-
enabled run by the implementation worker.

## 6. Estimated size

One small evidence module (roughly 80–140 lines), plus narrow edits to at most
three existing production callers and one focused test file (roughly 12–20
tests). Keep the total under about four production files/200 new production
lines; if strict packet semantics require more, stop and report the concrete
contract conflict instead of adding a framework.
