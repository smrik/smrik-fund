# P1 — smallest exact EdgarTools retrieval for the MSFT case

## Approach

Use the existing EdgarTools `EntityFiling` as the only filing source. Share one
latest-10-K filing object between statement loading and evidence retrieval so
`analyze MSFT --adjustments` does not perform a second filing lookup.

The installed EdgarTools version is 5.45.1. The relevant observed API is:

```text
Company("MSFT").get_filings(form="10-K").latest()
EntityFiling.search(query, regex=True) -> SearchResults
SearchResults.sections -> DocSection(loc, doc, score)
EntityFiling.text() -> exact plain filing text
```

The live latest filing is accession `0001193125-26-323660`, filed 2026-07-29,
period of report 2026-06-30, primary document `msft-20260630.htm`. Its standard
income statement is 21 x 19 with annual columns `2026-06-30 (FY)`,
`2025-06-30 (FY)`, and `2024-06-30 (FY)`; the target line is exactly
`Research and development`.

For the one known V1 topic (`restructuring` / XBOX impairment-related
expenses), issue only the two deterministic regex searches required by the
frozen case:

```text
Operating expenses increased \\$940 million ... impairment and other related expenses in our XBOX business
Research and development expenses increased \\$3.1 billion ... impairment and other related expenses in our XBOX business
```

The actual EdgarTools search hits are filing-section locators 196 and 201.
`EntityFiling.text()` contains the exact source lines at 1266 and 1283. Build
`E1` and `E2` from those exact lines, retaining original punctuation, casing,
bullet, and line text. Do not paraphrase or reconstruct from the search query.
The query strings are retrieval inputs only; they are not prompt instructions
and do not add the expected candidate or adjustment amount to the Analyst
prompt.

Write the packet to the existing deterministic topic path
`data/<TICKER>/03_output/evidence/restructuring.md` and return its text plus a
small metadata dict. The packet header should retain `ticker`, topic, form,
accession, filing date, period of report, primary document, filing URL/text URL,
and the retrieval method. Each evidence block should retain source section,
`EntityFiling` section `loc`, and the `EntityFiling.text()` line number. If a
search returns zero or multiple matching blocks, or a source-line match is
missing/ambiguous, fail closed instead of selecting a “best” fact.

The CLI should pass the saved packet string unchanged to the existing
`run_analyst()` call. The normal known-case path makes one filing/evidence
retrieval and one Analyst call. Keep the existing Reviewer-per-candidate and
risk-gate calls; do not add an Analyst revision or research loop for this case.
The current null amount stays null. A future research request, if later proved
necessary, must be a separately bounded one-retrieval/one-follow-up-Analyst
extension; do not add a schema field now merely to anticipate it.

## Changed surfaces

- `src/smrik_fund/ingestion/statements.py`: extract a small latest-filing plus
  statements-from-filing seam (or equivalent `build_analytical_pnl_with_filing`)
  while preserving the current `get_statements() -> dict[str, DataFrame]`
  contract. The adjustment path uses the shared filing; the existing
  non-adjustment path remains behaviorally unchanged.
- One small filing-evidence module (prefer a plainly named
  `ingestion/filing.py`; keep it functional): one known-topic retrieval
  function, exact-line extraction, packet writing, and filing metadata. No
  generic retriever or provider hierarchy.
- `src/smrik_fund/main.py`: replace the frozen-file-only input when
  `--adjustments` is active with the retrieved packet, save/pass that exact
  packet, validate evidence IDs before Analyst-result persistence, and include
  filing metadata in Analyst/Reviewer/manifest artifacts. Preserve the current
  Analyst -> Reviewer -> gate -> application order.
- Focused tests: fake an `EntityFiling` with `search()` and `text()` to prove
  exact excerpts, stable IDs, provenance, ambiguity failure, one retrieval, and
  one Analyst call. Extend the existing integration fixture for unresolved
  Xbox behavior and one eligible approved behavior.

## Invariants

1. Runtime filing text comes from EdgarTools. No web fallback, local raw-filing
   parser, duplicate SEC cache, RAG, embeddings, vector DB, or search framework.
2. The packet passed to Analyst and Reviewer is byte-for-byte the packet saved
   for that run. Display parsing may format fields but must not modify model
   input or quoted source text.
3. Evidence IDs are deterministic (`E1`, `E2`) for this fixed topic. Unknown
   candidate refs fail before Analyst-result persistence, Reviewer persistence,
   history mutation, or application.
4. Every excerpt retains honest filing identity and locator: accession,
   document/section locator, and source-text line when EdgarTools supplies it.
   Never invent a locator; use the search `loc` if a text line cannot be mapped.
5. A missing or ambiguous hit fails closed. No silent duplicate selection,
   amount substitution, period inference, target-line fuzzy match, or answer
   reconstruction.
6. The Analyst remains high-recall. `adjustment_amount=None` and
   `amount_basis="unknown"` remain unchanged when the filing does not disclose
   an attributable amount. Reviewer `suggested_amount` is never copied into
   the candidate.
7. The normal path performs at most one evidence retrieval and one Analyst
   resolution pass. Reviewer remains one call per candidate; no implicit retry
   or debate loop is introduced.
8. Reported P&L values and source reconciliation are immutable. Only the
   existing deterministic `resolve_current_adjustments()` and
   `apply_adjustments()` path may apply an approved amount.
9. Exploratory/unresolved/human-review candidates live in the run manifest and
   review JSON only; they do not append `proposed` rows to
   `adjustment_history.csv`, become current adjustments, or change adjusted
   P&L. Existing history bytes/rows remain unchanged. Only the existing
   authorized transition may append an approved row.
10. An auto-approved row retains candidate target, exact period, finite
    non-negative amount, evidence path/accession/topic, Reviewer and gate
    metadata, and unique version. Latest-version-first resolution remains
    unchanged.

## Non-goals

- No generic topic registry, retrieval abstraction, ranking/precision/recall
  system, vector/RAG layer, custom SEC parser, or second raw-filing cache.
- No cross-company or future-filing generalization beyond failing clearly when
  the known 2026 MSFT source pattern changes.
- No Analyst schema redesign, amount estimator, prompt hardcoding of the gold
  answer, target/period normalization beyond the existing exact contract, or
  Reviewer policy change.
- No research loop, Analyst revision loop, multi-topic batching, retries, or
  autonomous browsing. The known null-amount case goes to human review.
- No new history/application engine, human-review UI, direct `adjustments.csv`
  writes, cleanup of dirty data, commit, or push.

## Risks / verification

The largest retrieval risk is selecting the wrong one of several valid
mentions. Use regex search plus exact source-line matching and require one hit
per fixed evidence query. A fake filing test should return zero and duplicate
hits and assert both fail before packet/model persistence.

Prove exactness with punctuation, bullet, line-break, accession, search `loc`,
and source-line assertions. Assert the exact saved packet string is the exact
third argument to `run_analyst()` and the exact evidence string received by
each Reviewer. Assert `E99` fails closed before Analyst JSON/history writes.

Add call counters: one filing/retrieval operation and exactly one Analyst call
for the normal path. Add a null-amount test asserting no second Analyst call,
no inferred `$3.1 billion` adjustment, and `human_review` / `not_applied`.

Snapshot `adjustment_history.csv` bytes in a temporary output root. Run the
unresolved Xbox case and assert the file is absent or byte-for-byte unchanged,
the manifest preserves the candidate/review/gate details, and adjusted P&L
equals reported P&L. Seed one approved history row, rerun the unresolved case,
and assert it remains applied while history is unchanged. Separately prove one
fully eligible fixture appends exactly one approved row and applies only that
row through the existing engine.

Run the focused retrieval/integration tests, existing Analyst/Reviewer/gate,
adjustment, and reconciliation tests; then run the real
`smrik-fund analyze MSFT --adjustments` with available credentials/cache, Ruff
on changed files, and `git diff --check`. If SEC socket access or credentials
are unavailable, report that as an environment limitation, not as evidence of
retrieval correctness.

## Estimated size

Small bounded change: one concrete retrieval module (roughly 60–100
production lines), a small shared-filing seam in `statements.py`, and narrow
CLI plumbing (roughly 30–70 lines). Add about 100–160 focused test lines across
at most 3–5 files. No Analyst schema change is expected. More than four changed
production/test files or 200 new production lines indicates a generic layer or
history redesign and should stop for a scope decision.
