# P2 — filing workflow / judge / failure proposal

## 1. Filing execution contract

Use a static workflow adapter that invokes `investigate_finding(...)` once per case with a case-local `output_root` and injected counting client. Keep the existing sequence: deterministic seeds (`planner_call_count=0`), literal initial retrieval, at most one packet-grounded expansion/retrieval pass, then one `FinancialInvestigationResult` call. Enforce saved-scan accession/context identity before execution; reuse `validate_evidence_refs` and the existing retrieval metadata. Cite: `src/smrik_fund/ingestion/filing_investigation.py:2769-2855,3021-3367`; `src/smrik_fund/ingestion/filing.py:214-353`.

Map product outcomes explicitly: returned `completed` => `COMPLETED`; parsed structured output rejected by the financial validator => `VALIDATION_REJECTED`; client/retrieval/identity/serialization or uncaught workflow failure => `EXECUTION_ERROR`. Expansion rejection/no expansion is not invalid when the final investigation completes. Preserve `error_stage`, error text, and exact product/judge call counts.

## 2. Mechanical checks and normalized result

For `COMPLETED`, reload the saved JSON/evidence and re-run packet identity, accession/source locator, result-schema, evidence-ref, narrative numeric-free, period/sign/span, and deterministic reconciliation checks. Mark these critical; partial evidence, `not_computable`, unquantified drivers, or weak/no expansion remain valid diagnostics. Normalize only stable fields (status, observed movement, drivers, reconciliation, metadata); never normalize prose or manufacture residuals.

## 3. Judge contract and gating

Only mechanically valid completed outputs reach one separate native Structured Output judge call: `gpt-5.6-terra`, reasoning `high`, default sampling. Judge input is the frozen case rubric, normalized product result, observed movement, and exact evidence packet; output fixed dimensions (target/period, amount/basis, evidence grounding, movement-vs-cause separation, explanation) with ordinal `PASS|PARTIAL|FAIL` plus concise reasons. A judge error is `JUDGE_ERROR` while product stays valid; validation rejection/crash is `JUDGE_SKIPPED` and never scored.

## 4. Failure observability and artifacts

Create `eval-run/suites/<suite>/<case>/` before execution. Write authoritative `case.json` and compact Markdown, plus captured stdout, stderr, traceback, product artifact paths/hashes, frozen input identities, model/reasoning/prompt/schema, product/judge counts, and dirty/HEAD fingerprints. Catch a case exception, persist it, and continue the next case; do not let a failed case alter another case. Product outputs remain under that case root and are linked, not rewritten.

## 5. Small optional rejected-output hook

Add one optional `on_validation_rejection` callback at the final investigation validation boundary (after `_parse`, before the exception is raised), threaded through `run_financial_investigation`/`investigate_finding`. Callback receives only serializable pre-validation structured result, stage, and validator error; evaluator writes `diagnostics/rejected_output.json` with `trust=UNTRUSTED`, `status=REJECTED`, case/run ID, and hash. Never feed it to the judge, normalized result, canonical product state, or adjustment pipeline. This directly explains current live failures (numeric-free/unsupported causal or named-entity errors) whose JSON has `investigation=null`: `.../segment-aware-investigation/.../filing_investigation_02_rank2-live-diagnostic.json`; `.../filing_investigation_04_rank4-live-mini-diagnostic2.json`.

## 6. State-isolation proof

Run filing cases in distinct temporary case roots with a fake counting client; snapshot paths/hashes before/after. Assert only filing evidence + investigation JSON (and evaluator artifacts) appear; no `adjustment_history.csv`, `adjusted_pnl.csv`, reviews, or normalization/identity state, and patch the adjustment entry point to fail if called. Run two cases and assert the first root is byte-for-byte unchanged after the second. Existing proof seams: `tests/test_filing_investigation.py:650-685`; `tests/test_filing_investigation.py:1920-1970`.

## Control Block

- Recommendation: reuse `investigate_finding`; add only evaluator adapter, classifier, judge, and optional rejection callback.
- Product calls: normally two (expansion + investigation), zero/one allowed by no-query or expansion fallback; count exactly.
- Judge: one call only after critical checks pass; `JUDGE_ERROR` does not invalidate product.
- Invalid structured result: preserve pre-validation output as untrusted/rejected, never score or canonicalize.
- Each case gets an isolated output root; crash capture continues the suite.
- State proof requires no adjustment/history/review artifacts and unchanged prior case root.
- Evidence: current rejected live artifacts above; product seams and tests cited in §§1/6.
