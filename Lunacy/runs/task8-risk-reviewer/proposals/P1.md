## Reviewer contract and invariants

- `ReviewResult` is exactly the approved fields: `verdict` (`accept|revise|reject`),
  `evidence_strength`, `amount_basis`, `judgment_level`, nullable
  `calculation_valid`, `target_valid`, `concerns`, nullable `suggested_amount`
  and `note`; `extra="forbid"`.
- One call receives exactly one `AnalystCandidate`, the supplied reported P&L,
  and the caller-supplied evidence string. No file reads, retrieval, other
  candidates, hidden evidence, or Analyst re-run. Encode P&L missing values as
  JSON `null`, as Task 7 already does.
- Fail closed on candidate evidence references that are not present in the
  supplied packet (input-contract error before the API call); never let the
  model invent/resolve an unsupported citation. The supplied packet itself is
  the only usable evidence. This guard is not Task 9's approval gate.
- Prompt explicitly forbids silent proposal rewrites, fuzzy target/period
  matching, amount invention, and treating a mixed-driver line increase as a
  disclosed sub-item amount. `target_line` and `period` must match supplied
  P&L values exactly. Keep `suggested_amount=None` unless evidence-backed.
- A valid Xbox candidate with `adjustment_amount=None` and
  `amount_basis="unknown"` is a valid surfaced candidate: the Reviewer may
  accept the candidate's identification while recording unresolved amount
  concerns (`calculation_valid=None`). This is not an auto-approval decision.
- A fabricated `$3.1bn` Xbox/R&D impairment amount must be `revise` or `reject`
  with a concern that the cited `$3.1bn` is a mixed-driver R&D increase, not a
  separately supported Xbox impairment amount. Do not rewrite it to another
  number. Wrong target/period, unsupported evidence, and amount-basis
  misrepresentation must likewise produce a non-accepting verdict and an
  explicit concern (or fail-closed unsupported-reference error).
- `revise` is returned only; no revision loop, gate, approval, history, human
  workflow, adjustment application, retrieval, or Task 9 behavior in this task.
  A later orchestrator may perform at most one Analyst revision and one
  Reviewer re-check.

Task 7 path and is user-dirty. Do not add a generic validator, materiality or
duplicate framework, deterministic approval, revision runtime, retrieval, or
history writer. The main risk is model false acceptance of aggregate amounts;
the prompt and fixed fabricated-amount fixture must test that explicitly.

(~150–220 lines), no existing production-file edits. This stays below the
