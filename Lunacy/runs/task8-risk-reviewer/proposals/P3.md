# P3 — Task 8 Reviewer proposal

## Recommendation

Add one direct module, `src/smrik_fund/ingestion/reviewer.py`, and focused
`tests/test_reviewer.py`. Reuse `AnalystCandidate` from
`ingestion.adjustment_analysis`; do not alter the Task 7 module or wire a CLI
workflow yet. Expose `run_reviewer(candidate, pnl, evidence_packet, ...)` and
`save_reviewer_result(...)`.

The call is one candidate per `responses.parse` request. Its JSON payload has
only the normalized ticker, one candidate, the reported P&L records, and the
caller-supplied frozen evidence packet. Do not read filings, retrieve context,
batch candidates, or pass hidden evidence. Before calling OpenAI, reject
candidate evidence IDs absent from the supplied packet; preserve the packet
text exactly. Persist candidate, structured review, and run metadata under
`data/<TICKER>/03_output/reviews/<adjustment_id>_<run_id>.json`.

## Minimal contract

Use native Pydantic Structured Outputs (`extra="forbid"`):

```python
class ReviewResult(BaseModel):
    verdict: Literal["accept", "revise", "reject"]
    evidence_strength: Literal["strong", "medium", "weak"]
    amount_basis: Literal["disclosed", "calculated", "estimated", "unknown"]
    judgment_level: Literal["low", "medium", "high"]
    calculation_valid: bool | None
    target_valid: bool
    period_valid: bool
    concerns: list[str]
    suggested_amount: float | None = None
    note: str | None = None
```

`period_valid` is the only deliberate extension of the conceptual §15 schema:
the Task 8 acceptance and the later deterministic gate require wrong-period
handling. If the owner rejects this extension, retain the same signal in
`concerns`, but do not silently treat an unrecognised period as valid.

The prompt must say: compare target and period to exact supplied P&L values;
use only supplied evidence; do not silently rewrite the candidate; null amount
is unresolved, never zero; do not infer a sub-item amount from a parent-line
change; `suggested_amount` is advisory only. `revise` is returned for an
otherwise supported candidate needing a missing amount/basis; the module does
not implement the one-pass Analyst revision loop or Task 9 approval.

## Finance/evidence/API invariants

- A null amount/`unknown` basis remains valid structured input. For the frozen
  Xbox case (`Research and development`, `2026-06-30 (FY)`, E1/E2), preserve
  the candidate and explain unresolved attribution; conservatively return
  `revise` or `reject`, not `accept`/approval.
- Never accept a fabricated `$3.1bn` Xbox impairment: E2 describes the total
  R&D increase, not the impairment attribution. Return a non-accept verdict,
  no invented `suggested_amount`, and a concern naming the misattribution.
- Wrong target => `target_valid=false`; wrong/unavailable annual period =>
  `period_valid=false`; either must preclude `accept`.
- Unknown evidence IDs fail before persistence/API use. Existing IDs may be
  checked against the complete supplied packet; no external filing text is
  authoritative in this task.
- Serialize P&L missing values as JSON `null`; preserve reported signs and
  periods. Do not coerce candidate nulls to zero or mutate the DataFrame.
- Keep Reviewer verdict separate from final status/approval and from the
  deterministic adjustment engine.
