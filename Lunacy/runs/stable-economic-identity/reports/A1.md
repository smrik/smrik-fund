## Ranked findings
1. **P1 — mixed identities under one ID can replay.** `_history_identity_lookup` matches one row, then selects all rows for that `adjustment_id` without asserting their `_identity` is uniform (`src/smrik_fund/main.py:440-480`). Probe: A0001 v1 approved `xbox-impairment`, v2 rejected `gaming-impairment` returned `replay`; `_history_identity_complete` was `True`. This violates corrupted-history fail-closed and lets `resolve_current_adjustments` apply by ID. Require one identity per adjustment ID before lookup/application.
2. **P1 — malformed canonical history can abort instead of fail closed.** `_history_identity_complete` checks only `candidate_identity`/`candidate_state` and omits `adjustment_id`, `version`, `status`, numeric-version, and duplicate checks (`main.py:352-371`). Probe: otherwise-valid row without `status` returned `complete=True`; application resolver raised `ValueError: adjustment history is missing columns: status`. Use one full validator for lookup and application; invalid history must produce empty current state/unresolved, not abort.
3. **P2 — generic-key reviewer proof is prompt-only.** Prompt says reject generic `impairment` (`ingestion/reviewer.py:33-36`), but `ReviewResult` has no key verdict and a mocked `run_reviewer` accepted candidate `item_key="impairment"`. Downstream `_candidate_identity` rejects it (`main.py:304-305`), so no auto-apply; still missing the requested reviewer contract proof. Add a focused boundary test or deterministic post-review guard.
4. **P2 — row selector is duplicated, not reused.** `_source_line_indices`/`_target_row_key` (`main.py:149-279`) reimplement the existing label-first selector (`ingestion/adjustments.py:196-208`). Current duplicate-standard-concept fixture passes, but future selector drift can mint a different `target_row_key`; centralize/reuse the actual selector.
5. **P2 — proportionality is borderline.** The bounded change is net +157 production lines, mostly a 69-line row-key search and ~120-line history resolver/validator. No architectural bloat found, but centralizing F1/F2 validation and the selector should reduce rather than expand this delta.
