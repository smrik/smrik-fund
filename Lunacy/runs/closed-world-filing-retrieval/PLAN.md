# Closed-world progressive filing retrieval — Implementation Hive

## Goal

Replace answer-leaking first-pass searches with deterministic finding-grounded seeds, allow at most one provenance-checked filing-grounded expansion, and prove exact quantified MSFT evidence can drive safe Python reconciliation.

## Authority

1. `AGENTS.md`
2. `USER_NOTES.md`
3. Existing repository contracts/tests and completed prior run `Lunacy/runs/finding-driven-investigation/`
4. Lunatic Hive doctrine

## Phases

1. Diversity: three fresh read-only proposals covering closed-world seed generation, bounded expansion/provenance, and quantified bridge/live-proof design.
2. Synthesis/implementation: one fresh max-effort Luna judges proposals, implements the smallest coherent correction, performs terminal checks and fresh live MSFT proof.
3. Simplicity/financial adversary: one fresh read-only Luna attacks answer leakage, expansion provenance, quantitative attribution, no-plug arithmetic, and analyst usefulness. Correctness findings route to one serialized repair.
4. Repair if required: close authorized evidence/provenance defects, remove obsolete machinery, refresh verification/live proof.
5. Parent gate: targeted final diff/code/live-artifact inspection and bounded checks; verdict `PASS` or `DO NOT MERGE`.

## Gates

- Initial queries are deterministically derivable from persisted finding/line context; no company-specific answer leakage.
- Expansion occurs at most once; every follow-up literal is supported by prior retrieved filing text with auditable source evidence refs.
- Final evidence proves the discovery chain, not model memory.
- Quantified amounts/signs/periods reconcile only under exact evidence + unambiguous observed-line/period mapping; residual remains explicit and never a plug.
- Existing Scan, adjustment, normalization, materiality, identity, lifecycle, review, and financial state semantics unchanged.

## Verification ownership

- Implementer owns focused tests, relevant regressions, full suite, Ruff, `git diff --check`, final diff/stat, and fresh live proof.
- Adversary is read-only and runs bounded probes only.
- Parent runs one bounded acceptance sample/check set.
