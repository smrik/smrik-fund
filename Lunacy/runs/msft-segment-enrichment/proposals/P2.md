## Deterministic analytics

Emit one reported row per `(axis, member, metric, annual period)` in a separate
`segment_analytics.csv`. Retain exact concept, member QName and available
source label, axis, value, unit, period start/end, fiscal period/year,
`context_ref`, statement role, accession, filing date, source URL, and a
`reported` basis marker. Keep missing source values null. Reject an ambiguous
duplicate candidate instead of selecting one; member identity is QName/axis,
not display-label text. Do not force a member to be the same segment across
periods when the filing does not support that comparison.

For each member/metric, calculate only when inputs are finite/comparable:

- absolute YoY and guarded YoY matching `statements._safe_change` and scan
  positive-endpoint gate;
- Revenue `revenue_share` and share change in bps, using the consolidated
  Revenue row as denominator;
- Revenue contribution to same-period consolidated Revenue growth;
- Operating income `operating_margin` and margin movement in bps;
- Operating income contribution to same-period consolidated OperatingIncomeLoss
  growth.

For shares, margins, and contributions require a finite positive consolidated/
segment revenue denominator as applicable; require non-zero consolidated delta
for contribution. Missing, zero, non-positive/sign-changing growth endpoints,
non-finite values, unit mismatch, period mismatch, or ambiguous facts produce
N/A rather than a zero or an invented allocation. Preserve reported negative
values even when a derived metric is guarded out. No EBITDA or other undisclosed
profit metric.

## Reconciliation and persistence

Write a separate `segment_reconciliation.csv`, one row per metric/period, with
`reported_segment_total` (sum of complete disclosed members only),
`reported_consolidated_total` (the canonical P&L value), explicit
`residual = consolidated - segment total`, member list, unit/period metadata,
and status. Use exactly:

- `PASS`: same annual duration/unit/scope, all members unambiguous, residual
  within the existing 0.01-dollar presentation tolerance;
- `NOT_DIRECTLY_COMPARABLE`: complete values but a non-zero residual or known
  scope/period/unit mismatch;
- `UNRESOLVED`: missing values, duplicate/ambiguous facts, or no unique
  consolidated row.

Residual is inspection-only: never append, allocate, plug, or mutate reported
P&L. Current Note 18 totals are Revenue `331,839/281,724/245,122` and
Operating income `155,237/128,528/109,433` (USD millions as presented), so all
six checks should PASS at zero residual. The three segment Revenue series are
`139,996/120,810/106,820`, `137,791/106,265/87,464`, `54,052/54,649/50,838`;
Operating income is `83,879/69,773/59,661`, `56,972/44,589/37,813`,
`14,386/14,166/11,959`.

`save_segment_analytics` and `save_segment_reconciliation` should use the
existing `output_root/<TICKER>/03_output/` convention. In `main.analyze`, invoke
them only on `--scan` after the existing P&L/reconciliation work, using the
attached filing. Leave the adjustments path and all adjustment/state files
untouched. If a real filing is present but segment extraction is unsafe, fail
the segment-enriched scan clearly; synthetic tests with no filing may retain
the current consolidated-only path.

## Scan context and collision-safe refs

Keep every existing consolidated line and `L##` reference byte-for-byte stable
when no segment context is supplied. Append a compact `## Reportable segment
results` section: one line per discovered member/metric, containing three
period values plus only the relevant growth, mix/contribution, or margin/bps
metrics. Include a non-selectable reconciliation summary without a ref. Do not
send the raw facts table and do not add deterministic ranking/materiality.

Reserve a separate `S##` namespace for segment refs, assigned deterministically
by sorted member QName then fixed metric order (`Revenue`, `OperatingIncomeLoss`).
Store the ref mapping in the segment artifact. Extend the analytical-scan ref
regex/Pydantic pattern to `L##` or `S##`; `run_analytical_scan` and save-time
validation must derive allowed refs from the exact supplied context and reject
unknown/duplicate refs. Existing L refs remain valid. Bump the substantive
prompt version and add only generic instructions to compare segment growth,
mix/contribution, and operating margin to consolidated performance and copy
bare `S##` refs; never name or seed expected MSFT conclusions.

`filing_investigation.py` currently accepts/maps only L refs
(`:43-44,151-159,2215-2225,2600-2646`). Do not silently broaden retrieval in
this phase (USER_NOTES excludes filing investigation); record S-ref support for
the scan as the boundary and authorize a separate adapter before claiming that
`smrik investigate` can consume segment findings.

## Invariants, proof, and risks

Tests must prove exact source values/metadata and no source mutation; guarded
zero/missing/sign-change behavior; share/contribution/margin/bps arithmetic;
zero-plug residuals; PASS/non-comparable/unresolved statuses; deterministic S
refs under input reordering; S99 rejection; and L01 compatibility. Context tests
must show compact segment lines and no raw table. Run focused segment/scan/
reconciliation tests, Ruff, `git diff --check`, then the real MSFT extraction
and two scans (same filing/model/effort): preserved consolidated-only baseline
and enriched context. Compare ranked findings for new segment facts, retained
consolidated findings, mix/margin understanding, duplicate/slot noise, and
analyst time saved. The prior baselines are
`Lunacy/runs/analytical-scan/live-proof/...20260826T231439246775Z.json` (4
findings) and `data/live-closed-world-proof-r2/...20260827T190654525200Z.json`
(6 findings), both 19 consolidated refs; generate a fresh paired comparison.

Main risks are EdgarTools raw-fact field variation, duplicate contexts, member
recasts, and unit/period drift. Narrowly detect the observed raw fields and
fail closed on anything else. A direct EdgarTools live probe was blocked by
the environment socket ACL (`WinError 10013`); cached current filing/facts and
scan artifacts were read without edits. Estimated complexity: medium; roughly
120–160 new production lines in one focused module, 25–45 lines across scan/
CLI wiring, and two focused test surfaces. Stop before adding a taxonomy,
dimensional model, restatement engine, or downstream investigation adapter.
