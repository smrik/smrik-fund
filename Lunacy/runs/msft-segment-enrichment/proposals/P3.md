# P3 — compact Analytical Scan segment-context proposal

## Approach

Add one data-oriented `src/smrik_fund/ingestion/segments.py` seam. It receives
the filing already attached by `build_analytical_pnl()` and reads only that
filing's EdgarTools XBRL facts. Select facts by the disclosed
`StatementBusinessSegmentsAxis` dimension (not by Microsoft member names),
the four current-table concepts (Revenue, CostOfGoodsAndServicesSold,
OperatingExpenses, OperatingIncomeLoss), exact annual period ends, and a
single segment dimension. Preserve raw concept/member/unit/context/accession
fields; conflicting or unsafe facts remain unresolved, never silently picked.

Persist `03_output/segment_analytics.csv` (one source segment row with the four
reported measures and deterministic derived columns) and
`03_output/segment_reconciliation.csv` (metric/period, reported segment total,
reported consolidated total, explicit residual, status). Keep segment rows out
of canonical `analytical_pnl.csv` and run `reconcile_pnl()` unchanged.

Extend `format_analytical_pnl_for_scan(pnl, segments=None)` without changing its
default output. Append a short `Reportable segment context` section: one
selectable `line_ref=S##` per segment measure, with revenue growth/share/share
change/revenue-growth contribution and operating-income growth/margin/margin
change/operating-income contribution. Cost and operating-expense values may be
compact support lines. Assign S refs from sorted raw axis/member/metric identity;
consolidated `L##` refs remain byte-for-byte compatible. Accept only `L##|S##`
in the existing strict schema and exact supplied-ref validator. Bump prompt and
schema versions; prompt wording stays company-neutral and asks the model to
use segment context only when supplied, with no deterministic ranking.

Thread the same filing through `main.analyze --scan`, save both segment
artifacts, and pass the segment frame to the formatter before the existing
Responses call/persistence. Missing/unsafe segment facts yield an explicit
unavailable status and no selectable S ref; consolidated scan still proceeds.
`filing.py` remains text-evidence retrieval only. Existing
`filing_investigation.py` assumes every ref indexes canonical P&L (`L##` at
lines 43, 151, 532, 815); do not silently make S refs look like P&L rows. Either
add a small explicit S-ref rejection at that boundary, or separately plumb the
persisted segment context; the latter is outside this scan-focused proposal.

## Maintained surfaces

- New `src/smrik_fund/ingestion/segments.py`: extraction, period/comparability guards, metrics, persistence.
- `src/smrik_fund/ingestion/analytical_scan.py`: optional segment formatter, `S##` ref pattern, validation, metadata.
- `prompts/analytical_scan.md`: supplied-segment comparison instructions only.
- `src/smrik_fund/main.py`: same-filing segment build/save/context wiring; no adjustment branch changes.
- New `tests/test_segments.py`; extend `tests/test_analytical_scan.py` and CLI isolation; preserve P&L/reconciliation tests.
- Read-only source seams: `statements.py` (`get_statements`/filing attachment), `filing.py`, and `scripts/inspect_msft_edgartools.py`.

## Finance invariants

Reported signs, missingness, source periods, labels, units, concepts, context
IDs, accession, and reported-vs-derived separation are preserved. Guarded
growth follows existing positive-endpoint/nonzero semantics; zero, missing,
non-finite, and sign-change growth returns N/A. Shares require a nonzero
consolidated revenue; contribution ratios require a nonzero consolidated delta.
Margins/bps use finite comparable endpoints. No EBITDA, allocation, forecast,
adjustment, or invented recast/member mapping. Reconciliation never plugs:
residuals remain explicit and status is `PASS`, `NOT_DIRECTLY_COMPARABLE`, or
`UNRESOLVED`.

## Non-goals, risks, size

No taxonomy/ontology, geography, 10-Q, restatement engine, raw filing cache,
RAG, database, dimensional model, investigation retrieval, new LLM role, or
adjusted-P&L change. Main risks are facts tagged under multiple dimensions,
unit mismatch with canonical dollars, member/period drift, ref renumbering,
and `load_saved_scan()`'s exact P&L-context check; fail closed and test each.
Estimated scope: 1 new production module (about 180–260 lines), 3 existing
production files touched (about 70–120 lines), 1 prompt, 2–3 focused test
files (about 220–320 lines); medium complexity, no new dependency.
