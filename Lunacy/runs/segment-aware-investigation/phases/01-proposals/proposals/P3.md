# P3 — retrieval/evidence proposal

## Recommendation

Extend `src/smrik_fund/ingestion/filing_investigation.py` with one
namespace-aware resolver shared by plan context, observed movement, and
investigation. Keep `L##` positional behavior; resolve `S##` only from the
persisted segment table keyed by deterministic `segment_ref`, never by a
Microsoft name or prose. Require one safe PASS group per ref, consistent
label/axis/member/metric/unit/accession/source identity, and every saved annual
period in P&L order. Unknown, stale, duplicate, incomplete, inconsistent, or
non-reconstructable refs fail before retrieval/LLM. Mixed refs pass only after
all refs resolve.

For S rows, retain reported values and persisted derived fields (growth,
share/contribution, operating margin/margin change) as observed context; nulls
stay null and no context is recomputed. Include accession, URL, fact/context
IDs, and per-period provenance. Extend bounded plan context with segment label,
generic metric wording, periods, and movement facts. Initial seeds remain
literal, generic, and movement-first; static segment text is a marked fallback.
Never copy finding causes, member IDs, or filing prose into initial queries.
Existing `_select_initial_queries` and `filing.py` literal retrieval are sound.

Keep expansion packet-only and exactly one pass. Add only a prompt statement
that segment composition/mix is descriptive, not a consolidated cause; exact
evidence refs remain mandatory. Preserve numeric-free narrative, exact-span,
sign, period/unit, multi-driver, and no-plug validation. If any S ref exists,
reconciliation returns `not_computable` with no consolidated bridge/residual or
allocation; do not select an L ref silently. Preserve L-only bridge/artifacts.
