# P3 — CLI, tests, live proof, and whole-slice proposal

## Recommended approach

Implement one thin vertical scan slice around the existing `prepare_pnl()`
output. Keep accounting calculations in `src/smrik_fund/ingestion/statements.py`
and do not create a second P&L. Add one small
`src/smrik_fund/ingestion/analytical_scan.py` containing the deterministic
compact formatter, native Responses/Pydantic scan boundary, result validation,
and JSON persistence. Put the substantive prompt in the versioned
`prompts/analytical_scan.md` (loaded by that module, with an explicit prompt
version). This keeps the new role separate from adjustment Analyst/Reviewer
contracts while reusing their proven SDK pattern.

Extend the existing `analyze` callback in `src/smrik_fund/main.py` with
`--scan`, `--output-root`, and the existing model/reasoning options. Build and
save the canonical P&L, run the existing deterministic reconciliation, then
format/call/persist/render the scan. Reject `--scan --adjustments` rather than
allowing an accidental adjustment run. Thread `output_root` through the
existing deterministic saves and adjustment path so tests can isolate roots;
do not change adjustment behavior. Scan-only must never call
`_run_adjustment_analysis`, write `adjustment_history.csv`, or rewrite
`adjusted_pnl.csv`.

Use compact context row references generated from actual source row order and
metadata (for example `L01`, `L02`) and display the hierarchy explicitly as
`Revenue / Product` versus `Cost of revenue / Product`. Validator membership
must come from the formatter's supplied reference set, not a taxonomy or fuzzy
label matching. Persist the exact context beside the structured result so the
JSON is manually auditable.

## Maintained surfaces

- `src/smrik_fund/ingestion/analytical_scan.py`: formatter, strict
  `extra="forbid"` Pydantic finding/result models, rank/row-reference/count
  validator, `run_analytical_scan()`, and `save_analytical_scan()`.
- `prompts/analytical_scan.md`: only-supplied-context instructions; compare
  movements, growth, intensity, margins, mix, sign swings, non-operating,
  tax, and EPS relationships; observation versus explanation; no outside
  knowledge, causes, adjustments, normalization, forecasts, valuation, or
  recommendations.
- `src/smrik_fund/main.py`: `--scan` dispatch, output-root propagation,
  concise finance-first ranked rendering, and flag exclusivity. Existing
  `--adjustments` branch remains behaviorally unchanged.
- `tests/test_analytical_scan.py`: formatter, schema/validator, mocked API,
  persistence, and CLI isolation/side-effect coverage. Extend existing CLI
  tests only where needed to prove adjustment regression.
- Leave `statements.py`, `adjustment_analysis.py`, `reviewer.py`,
  `adjustments.py`, and reconciliation logic unchanged unless a minimal
  output-root plumbing edit is required by the acceptance tests.

### Whole-slice alternative

The smallest-file alternative is to put formatter, scan schemas, API call, and
persistence in `adjustment_analysis.py`, add the prompt file, and branch from
`main.py`. It saves one module but couples a new ranking role to adjustment
candidate semantics and risks reusing the wrong validation/history path. It is
acceptable only if a synthesis inspection proves no role-specific behavior is
shared; otherwise the one-purpose module is lower-risk and still small.

## Contracts and invariants

- Reported values, signs, missingness, periods, and EdgarTools metadata remain
  unchanged; `prepare_pnl()` remains the sole financial calculation source.
- Context includes FY24/FY25/FY26 values and existing applicable absolute
  change, growth, common-size, bps, and CAGR fields. Sign-crossing lines show
  absolute movement with `N/A` growth/CAGR, never invented percentages.
- Actual dimensional row order/metadata disambiguates both Product pairs;
  `GrossProfit` is shown as monetary gross profit despite its EdgarTools
  `Gross margin` label, while the dedicated margins/rates section separately
  shows gross, operating, pretax, net margins and ETR with FY values/bps.
- Abstract, empty, XBRL-noise, and duplicate alias rows are absent. EPS and
  share rows remain in a supplemental section without common-size metrics.
- Result is 0–8 findings. Every finding has unique ordered rank, title,
  high/medium/low importance, one or more supplied actual line references,
  observation, why-it-matters, and at most three questions; no extra fields.
  Python validates only shape/count/ranks/row references, not financial
  judgment.
- Responses API uses native `responses.parse(..., text_format=...)`; normal
  pytest injects a fake client and never needs an API key. Prompt receives only
  deterministic formatter output.
- JSON lives at
  `<output_root>/MSFT/03_output/analysis/analytical_scan_<run_id>.json` with
  ticker/company, available accession, run/model/prompt/timestamp metadata,
  context, and structured result. No adjustment history or adjusted model
  mutation is part of scan.

## Verification and live proof

Focused tests should prove: all three periods; R&D value/growth/intensity/bps/
CAGR; sign crossing; both Product hierarchies; GrossProfit/margin naming;
abstract/empty exclusion; EPS/shares; 0 and 8 valid; 9 rejected; duplicate or
non-ordered ranks rejected; unknown line refs rejected; mocked Responses call;
output-root isolation; unchanged adjustment history/adjusted P&L in scan-only.
Run the existing analytical-P&L, Analyst/Reviewer, adjustment/lifecycle tests
and then the full suite. Run Ruff on changed Python, `git diff --check`, and
inspect stat/diff. Current baseline is 143 passed / 45 subtests with the
conda environment plus `PYTHONPATH=src` and `-p no:cacheprovider`; `uv run`
is currently blocked by a uv-cache ACL, and the global CLI wrapper is not
installed against this checkout. Existing Ruff reports one unrelated
`reconciliation.py` B007.

With credentials, run in an isolated root:

```text
smrik-fund analyze MSFT --scan --output-root <scan-proof-root>
```

Manually compare saved context/result with the source P&L and confirm: FY26
other-income movement is +$15.598bn from FY25; gross margin 67.94% versus
68.82% (−88 bps) while operating margin is 46.78% versus 45.62% (+116 bps);
R&D intensity declines to 10.72%; Service and Other mix expands while Product
is nearly flat; pretax margin expands +612 bps; FY26 ETR is 19.40% (+177 bps).
These are human sanity checks only and must not be seeded into the prompt.

## Risks and size

Main risks are ambiguous duplicate labels, stale/string CSV values, filing
metadata unavailable when scanning a cached CSV, accidentally invoking the
adjustment branch, and over-validating model judgment. Address them with
stable formatter references, explicit numeric coercion/`N/A`, nullable
metadata, mutually exclusive flags, and shape-only validators. Preserve the
existing adjustment tests as a regression boundary.

Estimated scope: 2 production Python files (new scan module plus focused
`main.py` plumbing), 1 prompt, 1 focused test module, roughly 220–350 new
production lines and 250–350 test lines. No new dependency, provider layer,
taxonomy, command hierarchy, or source-data migration.
