# P1 — formatter and analytical-line identity

## Recommended approach

Keep `prepare_pnl()` as the only financial calculation source. Add one compact
presentation function, preferably
`format_analytical_pnl_for_scan(pnl: pd.DataFrame) -> str`, next to the
analytical-P&L code in `src/smrik_fund/ingestion/statements.py`. It should
return a deterministic Markdown context plus a small internal line-reference
map (or make the map derivable from the same formatter) so the scan boundary
can validate model references against exactly what it supplied. Do not create
a taxonomy or a second P&L.

Use annual columns in their existing source order, retaining the exact period
strings and displaying FY26/FY25/FY24 labels. Preserve source row order and
metadata. Give every included source row an opaque positional reference such
as `L01`; references are presentation IDs, not semantic mappings. Include the
source label and enough metadata to identify it, but never ask the model to
reconstruct identity from a paraphrased label.

For dimension/breakdown rows, derive a display parent only from actual
metadata and source ordering: in the current MSFT frame, a Product row sharing
the preceding total's concept is rendered `Revenue > Product`, while the later
same-label row is `Cost of revenue > Product`. Likewise render Service and
Other under the correct parent. If metadata cannot establish a parent, retain
the literal label and mark the row as dimensioned; do not guess a taxonomy.

Emit three deterministic sections:

1. `Line movements`: all non-abstract, non-empty, non-noise monetary source
   rows (including totals and dimensional rows), with FY26/FY25/FY24 values,
   applicable absolute YoY change, guarded growth, common-size, common-size
   bps change, and two-year CAGR. Render unavailable or mathematically
   meaningless metrics as `N/A`; never turn missing values into zero. A sign
   crossing keeps its absolute movement and gets `N/A` growth/CAGR. For the
   monetary `GrossProfit` concept, display e.g. `Gross profit (reported label:
   Gross margin)` without changing the source DataFrame.
2. `Margins and rates`: gross, operating, pretax, and net margin plus ETR,
   with all three levels and bps changes. Label the derived ratio explicitly
   (`Gross margin ratio`) so it cannot be confused with the reported monetary
   GrossProfit row.
3. `EPS and shares`: basic/diluted EPS and weighted-average shares with values
   and ordinary movement metrics if available, but no percent-of-revenue or
   common-size metrics. Keep abstract/empty headers out.

Only suppress an exact duplicate display alias when all source identity,
dimension metadata, selected period values, and row role are equal; preserve
non-identical duplicates and their ambiguity. This avoids collapsing the two
real `SellingGeneralAndAdminExpenses` rows or the two Product rows. Abstract
rows, rows with no selected-period value, and structural/XBRL-noise rows are
excluded by explicit metadata/finite-value checks, not by a broad label list.

The scan LLM module should consume only the resulting context string. Its
mechanical post-check owns the allowed line-reference set emitted by the
formatter. This is the key boundary: Python decides what facts and references
exist; the model ranks attention and writes observations/questions only.

## Maintained surfaces

- `src/smrik_fund/ingestion/statements.py`: formatter and any tiny local
  display helpers; reuse the already-present deterministic metrics in
  `prepare_pnl()`.
- `src/smrik_fund/ingestion/analytical_scan.py` (new, if needed): scan result
  schema, context/reference handoff, mechanical rank/reference validation,
  Responses call, and JSON persistence. Keep it a role module, not a provider
  framework or calculation layer.
- `prompts/analytical_scan.md` (new): substantive versioned scan prompt,
  loaded by the scan role and committed with the code.
- `src/smrik_fund/main.py`: add the coherent `--scan` branch and thread the
  existing `output_root` through P&L/reconciliation persistence. Scan-only must
  never call `_run_adjustment_analysis()`.
- `tests/test_analytical_scan.py` (new, focused): formatter, schema,
  persistence, mocked Responses call, and CLI isolation cases. Preserve
  existing Analyst/Reviewer/adjustment tests unchanged except for necessary
  import/CLI compatibility.

Do not alter `adjustments.py`, `adjustment_analysis.py`, or history semantics.
The existing `analysis/` directory and run-ID filename convention are enough;
write `data/<ticker>/03_output/analysis/analytical_scan_<run_id>.json` under the
passed output root, containing exact context, metadata, and structured result.

## Non-negotiable invariants

- `prepare_pnl()` remains canonical; formatter is presentation-only.
- Reported values, signs, missingness, periods, row order, and useful EdgarTools
  metadata are preserved. `NaN` is shown as `N/A`, never as zero.
- `L01`-style refs map one-to-one to actual supplied rows; affected refs in a
  result must be known, with no fuzzy labels or invented rows.
- Product and Service/Other remain qualified by their actual parent context.
- GrossProfit monetary value and derived gross-margin ratio remain distinct.
- EPS/share rows never receive fake revenue-intensity metrics.
- All schema extras are forbidden; findings count is 0–8, ranks are exactly
  `1..n` in order, and each finding has at most three questions. Python checks
  only these mechanical contracts, not the model's financial judgment.
- Scan output is append-by-run JSON and never enters `adjustment_history.csv`,
  `adjusted_pnl.csv`, or adjustment discovery/review.
- Normal tests inject a fake Responses client/frozen result; no live LLM call.
- Output-root isolation is complete: no implicit writes to the repository's
  default `data/` when a test or caller passes another root.

## Main risks and verification

- **Wrong hierarchy / duplicate labels:** assert context contains
  `Revenue > Product` and `Cost of revenue > Product` (and analogous Service
  rows), with distinct refs; test repeated standard concepts and exact alias
  duplicates.
- **Gross margin ambiguity:** test a GrossProfit row labeled `Gross margin`
  and assert both the reported monetary row and a separate ratio section.
- **Metric distortion:** fixture R&D, a negative-to-positive other-income
  line, missing values, zero prior, and negative endpoints; assert all three
  periods, absolute movement, guarded `N/A`, common-size/bps, and CAGR.
- **EPS/share pollution:** fixture EPS and shares and assert no
  `percent_of_revenue`/common-size tokens on those lines.
- **Model contract failures:** unit-test >8 findings, extras, duplicate or
  non-ordered ranks, unknown refs, and >3 questions; test zero findings.
- **State mutation:** invoke `analyze MSFT --scan` with a temporary
  `--output-root`, mock build/client, snapshot the root, and assert no history
  or adjusted P&L is created/changed and JSON/context is inspectable.
- **Regression:** run focused scan/formatter tests, existing analytical-P&L,
  Analyst/Reviewer, adjustment/lifecycle tests, full pytest, Ruff on changed
  Python, `git diff --check`, and inspect diff/stat. If credentials exist,
  manually compare a real scan context/result with the current P&L; do not
  seed expected MSFT answers in tests or prompt.

## Size / complexity

Expected bounded change: one formatter addition, one small scan-role module,
one prompt, one CLI wiring change, and one focused test module (roughly 3
production Python files plus prompt/tests; about 150–300 net production lines).
If implementation requires a new taxonomy, persistence service, cache
framework, adjustment integration, or more than roughly four production files
or 450 net production lines, stop for a decision brief.

## Explicit non-goals

No filing retrieval or explanations, segment extraction, new statement
architecture, normalization/adjustment actions, forecasting, valuation,
recommendation, scoring formula, RAG/vector DB, provider abstraction,
database/UI/background orchestration, or edits to the existing Analyst,
Reviewer, risk gate, adjustment engine, or history state.
