# Issue tracker: GitHub

Use [this repository's issues](https://github.com/smrik/smrik-fund/issues) for tasks and
[pull requests](https://github.com/smrik/smrik-fund/pulls) for implementation and feedback.
Prefer the connected GitHub tools; `gh` is a fallback when available and authenticated.
Verify the owner and repository before writing. Search existing issues before creating one.
Preserve current boards, milestones, and labels. Do not invent labels without checking
what exists. Status can be stated in the issue body.

Read the issue, its comments, and linked evidence before work. Link the PR and report
completion checks. A label or comment alone does not guarantee agent execution.
PRs as a request surface: no.

For triage roles, read `docs/agents/triage-labels.md`. Use its body-field mapping
while preserving existing labels and boards.
